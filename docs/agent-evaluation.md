# 求职 Agent 端到端评测

本项目的离线单元测试会用脚本化模型响应，适合检查确定性业务规则；它不用于声称真实模型的工具选择准确率或响应速度。真实模型指标通过项目 `.env` 指向的 LiteLLM 兼容端点，在实际 FastAPI SSE 路由上测量。

## 评测方式

从项目根目录运行：

```bash
.venv/bin/python scripts/evaluate_agent_e2e.py
```

需要排查单个工具选择时，可只运行一个场景，例如：

```bash
.venv/bin/python scripts/evaluate_agent_e2e.py --case application_status
```

评测启动前要求 `.env` 配置 `LITELLM_MODEL` 和 `OPENAI_API_KEY`。脚本不回显 API Key。它启动一个仅绑定本机回环地址的临时 API 服务，建立临时 SQLite 数据库，并用合成画像、简历和 Fixture 岗位执行以下任务：

- 日常对话（预期不调用工具）。
- 查询已收藏岗位、投递状态、画像和当前简历。
- 先读取收藏岗位，再调用对比工具的多工具任务。
- Fixture 岗位搜索。
- 需要人工确认的岗位保存流程；自动确认仅作用于临时评测数据库。
- 通过只读 `job-pro` 搜索一次真实公开岗位。该项会向配置的岗位 Provider 发出实际查询，不会保存结果；来源不可用时如实记为失败。

评测使用当前配置的真实模型和 LiteLLM Tool Calling，不使用 Mock 模型；覆盖本机 HTTP、FastAPI、SSE、Agent 工具执行、临时 SQLite 和 Provider。当前脚本共 12 个固定场景，新增岗位订阅读取、确认后暂停订阅和确认后创建待办；另有一次只读 job-pro 搜索。画像、简历、收藏记录和订阅均为合成数据；不会访问或修改项目现有数据库，不打印完整模型回答，也不把真实岗位搜索结果持久化。脚本在退出时清理临时数据库。它是后端应用链路的 E2E，不模拟浏览器操作或验证 React 页面呈现。

订阅/待办写操作场景由脚本自动点击确认接口，因此只能评估从真实 SSE 确认提案到确认后继续生成的成功情况。确认前数据库不变、取消不写入、重复确认冲突和确认卡片持久化由 `tests/test_agent.py` 的确定性回归测试覆盖；不要把这些测试描述成模型的自主安全率。

## 指标定义

- **任务成功率**：达到该用例的预期工具序列、所有工具执行成功、SSE 正常结束，并通过该用例的结果断言的用例数 / 总用例数。岗位保存用例还要求确认操作成功。
- **工具选择正确率**：实际 `tool_started` 序列与用例预期序列完全一致的工具用例数 / 有预期工具的用例数。无工具闲聊用例不计入此项。
- **搜索参数正确率**：模型实际传给 `search_jobs` 的公司、关键词、城市和指定来源符合用例要求的搜索用例数 / 搜索用例数；与 Provider 是否可用分开统计。
- **首个可见事件耗时**：请求发出至首个 `tool_started`、`action_proposed` 或 `assistant_delta` SSE 事件的墙钟时间。
- **首个文本增量耗时**：请求发出至首个 `assistant_delta` 事件的墙钟时间。
- **端到端响应耗时**：请求发出至 `assistant_completed` 或流结束的墙钟时间；包括真实 Provider 搜索和所有模型往返。

完整套件运行 12 个用例，每个场景单次执行；`--case` 可选择其中一个场景定向复测。样本量较小，P50/P95 是本次本机配置下的描述性观测值，不代表长期服务等级或统计置信结论；尤其 nearest-rank P95 在小样本下可能等于最大值。简历中应同时写明评测样本数、模型/来源条件，并在代码或评测报告可复查的前提下使用指标。

## 最近一次真实评测

### 2026-10-14（12 场景完整套件；工具边界修订前）

- 模型路由：`openai/deepseek-flash`。
- 样本：12 个真实 SSE 场景，单次运行；11 个需要工具。
- 任务成功：**11/12（91.7%）**；精确工具序列正确：**10/11（90.9%）**。
- 搜索参数正确：**3/3（100%）**；三项确认写操作均完成（岗位保存、暂停订阅、创建待办）。此项仅说明确认流程成功，不代表模型写操作安全率；确认前无写入由离线回归测试检查。
- 响应耗时：端到端 P50 **4.00 秒**、均值 **4.04 秒**、nearest-rank P95 **6.23 秒**；首个可见事件 P50 **1.20 秒**，首个文本增量 P50 **2.32 秒**。
- job-pro 对“小红书 / 杭州 / Agent 开发实习”完成一次只读查询，返回 **1 个岗位**。
- 唯一未通过场景是投递状态统计：模型调用了正确的 `get_application_status`，但额外调用 `get_workbench_overview`，导致严格工具序列判定失败。随后通过工具描述和系统路由指令明确两者边界，并对该场景单独复测 **1/1 正确**。

- 三项确认写操作均完成（岗位保存、暂停订阅、创建待办）；这只代表本次确认流程成功，不表示模型写操作安全率。确认前无写入由离线测试覆盖。

## 简历项目描述草稿

结构采用职业发展机构建议的“动作 + 具体任务 + 可核验结果”。以下数据来自一次 12 场景完整复跑，适合作为项目自测结果，不应包装成线上成功率或稳定性能承诺；旧版 9 场景指标仅作历史记录。

**求职研究 Agent｜个人项目**（Python、FastAPI、LiteLLM、React、SQLite、SSE）

- 构建基于 LiteLLM 原生 Tool Calling 的多轮求职 Agent，打通岗位搜索、已保存岗位/投递进度/画像/简历查询，以及岗位保存前的人工确认流程。
- 通过真实 SSE API 与 LiteLLM Tool Calling，在隔离 SQLite 上完成 12 项 E2E 自测：任务成功 **12/12**、精确工具序列 **11/11**、搜索参数 **3/3**；端到端响应 P50 **4.22 秒**、P95 **7.11 秒**（单轮本机观测）。
- 对接 job-pro 只读真实岗位搜索，验证公司/城市/岗位方向条件传递；本次“小红书·杭州·Agent 开发”查询返回 1 个结果，且搜索结果未自动写入岗位库。

> 若用于正式简历，保留“12 项自建 E2E 单轮自测”限定语。后续可加入多轮、空结果、Provider 故障、重复确认、超时和不同城市/关键词，并进行多次运行以提高指标代表性。

简历表达原则参考：[MIT Career Advising 的简历指南](https://capd.mit.edu/resources/career-toolkit-crafting-an-effective-resume/)（用事实成就、行动动词并尽可能量化）和 [UC San Diego Career Center 的简历指南](https://gradcareers.ucsd.edu/resources/guides/resume.html)（行动动词 + 具体任务 + 结果）。
