# Job Analysis Agent 实施计划

本文档是工程实施顺序和阶段验收标准。每完成一个阶段，都必须完成对应的离线测试和最小端到端验证，再进入下一阶段。

产品需求见 [PRD.md](PRD.md)，技术约束见 [design/architecture.md](design/architecture.md)，数据库约束见 [design/data-model.md](design/data-model.md)，接口约束见 [design/api-contract.md](design/api-contract.md)。

MVP 后续版本的产品范围见 [PRD-v0.2.0.md](PRD-v0.2.0.md)。Phase 9–12 共同构成 v0.2.0，按顺序分阶段实施。按用户决定，Phase 9 工作台先行开发；Phase 7、8 的整体验收已完成，v0.2.0 已具备发布条件。

## 总体路线

```text
工程初始化
    ↓
Fixture 岗位搜索
    ↓
收藏与岗位状态
    ↓
画像、简历和记忆

    ↓
前后端完整联调
    ↓
真实合规 Provider
    ↓

```

## Phase 1：Fixture 岗位搜索闭环

### 目标

先不接真实招聘网站，使用 Fixture 数据完成“输入条件 → 规则筛选 → API 返回岗位”的完整闭环。

### 后端任务

1. 定义 `JobSearchRequest`、`JobSummary`、`JobSearchResponse` 等 API Schema。
2. 完善 `FixtureProvider`，提供不同城市、发布日期、薪资状态、实习类型和岗位方向的数据。
3. 实现岗位标准化和来源标记。
4. 实现 `jobs` / `job_snapshots` Repository。
5. 实现关键词、城市、发布日期、薪资状态、实习条件筛选。
6. 实现 `POST /api/v1/jobs/search`。
7. 实现 `GET /api/v1/jobs/{job_id}`。
8. Provider 结果为空、部分失败和全部失败返回明确质量摘要。

### 前端任务

1. 将岗位搜索页的表单连接到真实 API。
2. 展示加载、空结果和 Provider 失败状态。
3. 展示岗位来源、发布日期和薪资未公开状态。
4. 搜索结果不自动收藏、不自动调用 LLM。

### 验收

- 使用 Fixture 搜索上海后端实习可以返回岗位。
- 最近 3 天只按照 `published_date` 筛选。
- 未公开薪资不会显示为 0。
- Provider 错误不会被伪装成空结果。
- 前端可以完成一次真实搜索。

### 实际交付

- Fixture Provider 提供上海、杭州和北京的技术实习岗位样例，包含已公开、未公开和未知薪资状态。
- `JobRepository` 完成岗位 upsert、来源登记和 `job_snapshots` 内容去重。
- `POST /api/v1/jobs/search` 支持关键词、城市、发布日期、薪资状态、实习类型和分页。
- `GET /api/v1/jobs/{job_id}` 返回标准化岗位和最新快照。
- 前端岗位搜索页已接入 API，展示来源质量、加载、空结果、失败、岗位详情和来源链接。
- 收藏按钮保持禁用，不伪造 Phase 2 尚未实现的保存行为。

### 验收结果

- 上海、最近 3 天、实习生筛选返回 2 个 Fixture 岗位。
- 最近日期筛选使用 `published_date`，不使用抓取时间。
- 未公开薪资返回 `null` 数值和“薪资未公开”文本。
- 未配置 Provider 返回 `502 provider_unavailable`，不会伪装成空结果。
- 后端 6 个离线测试通过，前端 lint 和 production build 通过。

## Phase 2：收藏和岗位状态管理

### 目标

完成“搜索结果 → 收藏 → 岗位管理 → 用户维护状态”的闭环。

### 后端任务

1. 初始化当前单用户 `candidate_profile` 和默认“已保存”状态。
2. 实现 `applications` Repository 和唯一约束处理。
3. 实现用户自定义状态 CRUD。
4. 实现收藏、取消收藏关系读取和分页。
5. 实现状态修改事务：更新当前状态并写入历史事件。
6. 实现状态生效时间和备注。
7. 实现岗位管理 Tab：全部、待分析、已分析。

### API

```text
GET    /api/v1/applications
POST   /api/v1/applications
GET    /api/v1/applications/{id}
PATCH  /api/v1/applications/{id}
POST   /api/v1/applications/{id}/status
GET    /api/v1/applications/{id}/timeline
```

### 验收

- 搜索结果点击收藏后出现在岗位管理。
- 重复收藏返回 `409 already_exists`。
- 用户修改状态后，当前状态和历史事件同时保存。
- 系统不会自动把岗位标记为已投递或面试中。
- 刷新页面后仍可读取岗位和状态历史。

### 实际交付

- 单用户画像首次收藏时自动初始化，并创建 6 个可维护的默认状态。
- 新增收藏、收藏列表、收藏详情、备注更新、状态变更和状态时间线接口。
- 新增状态定义查询、创建、修改和停用接口。
- 状态修改和状态事件在同一事务中保存；生效时间来自用户输入或当前时间。
- 岗位搜索页的收藏按钮已接入 API，岗位管理页已接入全部、待分析、已分析三个 Tab。
- 岗位管理页支持修改状态、保存备注、打开岗位链接和查看状态历史。

### 验收结果

- 重复收藏返回 `409 already_exists`。
- 状态变更后当前状态和时间线同时更新。
- 系统不会自动把岗位变成已投递、面试中或 Offer。
- 后端 8 个离线测试通过，前端 lint 和 production build 通过。

## Phase 3：个人画像、简历和长期记忆

### 目标

让用户维护可确认、可查看、可编辑、可删除的求职画像，而不是使用一条不可解释的画像 JSON。

### 后端任务

1. 实现画像读取和更新。
2. 实现多个简历版本和当前简历切换。
3. 实现 `profile_facts` 的新增、编辑、逻辑删除。
4. 实现 active、superseded、deleted、temporary 状态。
5. 实现 Agent 画像摘要确认接口。
6. 实现敏感信息脱敏函数。

### 前端任务

1. 接入个人画像页面。
2. 支持编辑求职方向、城市、实习时间和技能。
3. 支持简历版本列表和当前版本切换。
4. 支持记忆查看、确认、修改和删除。

### 验收

- 一次临时搜索不会自动修改长期画像。
- 用户确认后才会写入 active 事实。
- 新方向可以 supersede 旧方向，旧记录仍可查看。
- 手机号、邮箱、身份证和详细住址不会进入 LLM Prompt。

### 实际交付

- 新增个人画像查询和更新接口，支持目标方向、城市、实习时间、出勤天数和关注行业。
- 新增多简历版本接口，支持创建、查看、预览和选择当前简历。
- 新增画像事实接口，支持 temporary、active、superseded、deleted 生命周期。
- 新增画像确认接口；用户确认后事实才会进入 active 画像。
- 删除画像事实采用逻辑删除，不破坏历史记录。
- 新增本地敏感信息脱敏函数，简历预览和未来模型上下文可复用。
- 个人画像页已从静态占位改为真实 API 联调。

### 验收结果

- 临时画像事实默认不会出现在 active 列表。
- 确认后事实进入 active，删除后进入 deleted。
- 多个简历版本只能有一个当前版本，首个版本自动成为当前版本。
- 简历预览会脱敏手机号和邮箱。
- 后端 10 个离线测试通过，前端 lint 和 production build 通过。

### 后续扩展：附件简历自动解析

- 增加 PDF/DOCX 附件上传、本地文本提取、显式模型处理同意、结构化解析草稿和用户确认保存。
- 在线简历使用结构化字段展示；编辑已有版本时另存新版本，附件来源可追溯，删除附件不删除在线简历或历史分析。
- 岗位分析上下文同时包含脱敏后的简历原文和结构化简历内容。
- 离线测试覆盖文档校验、同意边界、模型解析、人工确认、附件删除和隐私脱敏。

## Phase 4：真实岗位来源与人工确认保存（已完成）

### 已完成

- 增加 `boss-agent-cli` 只读搜索 Provider；适配 JSON 信封、超时、登录失效和工具未安装错误。
- 增加 `job-pro` 只读 Provider；通过公司公开招聘接口搜索中国校招实习岗位，适配公司结果、岗位链接、来源 ID、城市和部分失败状态。
- 搜索结果只保存在当前进程临时缓存，不会自动写入 `jobs` 或 `job_snapshots`。
- 增加通用公开岗位链接提取预览：优先解析 JSON-LD，必要时渲染 JavaScript 页面，再由 LLM 按原文证据抽取并允许用户校对；不登录或绕过站点限制。
- 增加确认保存接口；用户确认后才写入 `jobs` 和 `job_snapshots`。
- 保存岗位时记录来源、授权模式、来源链接和提取方式。
- 前端增加 Provider 选择和来源/提取方式展示；岗位链接导入 API 保留在后端，第一版搜索页暂不提供入口。

### API

```text
POST /api/v1/jobs/search
GET  /api/v1/jobs/search-results/{result_token}
POST /api/v1/jobs/search-results/{result_token}/save
POST /api/v1/jobs/import/preview
POST /api/v1/jobs/import/{preview_token}/confirm
```

### 验收结果

- Fixture 搜索不会新增数据库岗位；确认保存后才新增岗位和快照。
- `boss-agent-cli` 已安装并通过 `boss schema --format native` 验证 JSON 能力契约；真实搜索仍需要用户在 BOSS 本地完成登录。
- `job-pro` 已用字节跳动和腾讯的公开实习搜索结果完成在线 smoke 验证；它是可选依赖，未安装时仅将该来源标记为不可用，不影响离线 Fixture 和其他来源。
- 无效链接返回 `invalid_job_link`，不会写入数据库。
- 后端 13 个离线测试通过，前端 lint 和 production build 通过。

## Phase 5：岗位详情和匹配分析

### 目标

完成“用户主动选择岗位 → 读取岗位快照和画像 → LLM 结构化分析 → 保存匹配结果”。

### 后端任务

1. 实现岗位详情、最新快照和来源证据查询。
2. 实现岗位匹配 Prompt Builder。
3. 实现 LiteLLM Adapter 和超时配置。
4. 实现结构化 JSON 解析、Markdown JSON 清理和 Pydantic 校验。
5. 实现匹配结果保存和历史查询。
6. 加入日期、薪资和来源引用约束。
7. LLM 失败时不创建成功报告。

### API

```text
POST /api/v1/jobs/{job_id}/matches
GET  /api/v1/jobs/{job_id}/matches
GET  /api/v1/matches/{match_id}
```

### 当前进展

- 已完成岗位详情页的“保存并分析 / 分析岗位 / 重新分析”入口。
- 已完成 `POST /api/v1/jobs/{job_id}/matches`，只读取已保存岗位、最新岗位快照、当前画像和当前简历。
- 规则初筛作为辅助证据，LiteLLM 基于画像、脱敏简历和最新岗位快照生成结构化语义分析并保存 `job_matches`。
- 未配置模型或生成失败时明确返回错误，不写入成功匹配记录。
- 搜索结果仍然是临时结果，不会因为搜索自动写入 `jobs` 或 `job_snapshots`；用户主动点击后才保存。

### 后续验收

- 只有用户点击“分析岗位”才进入匹配分析流程并调用 LiteLLM。
- 报告包含六类核心字段。
- 报告能关联使用的岗位快照、简历版本和来源证据。
- 未公开薪资不被模型补成具体数字。
- 使用 Mock LLM 测试合法 JSON、代码块 JSON、非法 JSON、超时和 Provider 缺失。

## Phase 6：求职 Agent、工具调用和 SSE

### 目标

让 Agent 能进行一般求职对话、搜索岗位、查询和比较已保存岗位、查询画像/简历、分析岗位，并在用户确认后修改或移除本地记录。会话和运行过程可持久化并恢复。

### 后端任务

1. 实现 Agent Session、Message、Run Event Repository 和 Alembic 迁移。
2. 实现 LiteLLM 原生 Tool Calling：岗位搜索、收藏岗位/详情/对比、状态、画像、简历读取和匹配分析。
3. 对岗位状态/备注、移除跟踪、收藏、画像和简历修改生成待确认提案，由用户确认后调用现有 Service。
4. 搜索结果保持临时状态；Agent 不自动保存岗位或投递。
5. 保存每轮消息和运行事件，支持新建、重命名、切换及继续历史会话。
6. 使用最近 12 条消息和选择性召回的成功工具证据；不宣称无限上下文或自动摘要压缩。
7. 实现 POST SSE 事件顺序、断线后事件读取和成功/失败终止事件。
8. 前端接入 Markdown、运行进度、工具事件和确认卡片。

### 验收

- Agent 能通过工具回答一般求职问题，并可真实搜索岗位、查询/比较保存岗位、状态、画像和简历。
- 同一会话的多轮消息被保存；用户可切换、重命名历史会话并继续交流。
- 工具失败会如实返回；同一轮不重复尝试相同失败来源，也不以 Fixture 冒充真实数据。
- 岗位收藏、状态/备注修改、移除跟踪、画像和简历修改均需要显式确认。
- 移除跟踪不删除岗位主记录、来源快照和匹配分析。
- 每轮以成功或失败事件终止；页面不展示隐藏推理过程。

### 实际交付

- 增加 `/api/v1/agent/*` 会话、消息、工具目录、SSE 对话、运行事件查询和待确认操作接口。
- 使用 LiteLLM 原生流式 Tool Calling，支持岗位搜索、岗位管理查询和对比、投递状态、画像和当前在线简历查询、岗位匹配分析。
- 一般聊天无需调用工具；实时岗位或个人数据问题要求工具查证。
- 更新/移除岗位跟踪、收藏、画像修改和简历修改先以确认卡片呈现，确认后才写入。
- 求职 Agent 页面支持多轮对话、Markdown、运行事件、操作确认，以及历史会话创建、重命名、切换和继续。
- 消息原文留在本地数据库；联系方式在模型上下文前脱敏，简历修改保留本机联系人字段。

### 验收结果

- 离线回归覆盖工具调用、搜索结果不自动入库、会话续聊、岗位对比、操作确认/取消、画像和简历修改、移除岗位数据保留及 PII 脱敏。
- 前端通过 lint 和 production build；整体真实模型/真实招聘源端到端验收仍需使用本地 `.env` 和可用 Provider 执行。

## Phase 7：前端真实联调和页面完善

### 目标

将五个原型页面从静态占位升级为真实 API 页面。

### 页面顺序

1. 岗位搜索：搜索、筛选、分页、收藏。
2. 岗位管理：Tab、详情、状态、备注、分析结果。
3. 个人画像：画像、简历、记忆。
4. 工作台：最近搜索、待处理岗位、最近分析。
5. 求职 Agent：多轮对话、工具事件、Markdown 和来源展示。

### 验收

- 页面只通过 API 访问数据，不直接读取 SQLite。
- 搜索、收藏、状态修改、分析和 Agent 可以连续操作。
- 加载、空状态、错误、SSE 断开和重试状态清晰可见。
- 前端类型与 API 契约一致。

## Provider 设计约束

真实 Provider 已前置到 Phase 4，但必须保持以下边界：

- BOSS 只通过用户本地的 `boss-agent-cli` 进行只读搜索。
- 不保存平台 Cookie，不自动登录，不自动投递，不绕过验证码或风控。
- 链接导入只读取公开页面；LLM 后续只能解析已经获取的页面内容。
- Provider 失败必须透明返回，不能用 Fixture 结果伪装真实来源。

## Phase 8：稳定性、安全和交付收敛

## 后续版本阶段摘要

详细产品行为与验收标准以 [PRD-v0.2.0.md](PRD-v0.2.0.md) 为准；本节只记录实施顺序。

### Phase 9：求职工作台 2.0（v0.2.0）

- 复用现有岗位收藏、自定义状态及状态事件，完成可筛选的真实状态看板，并提供状态快速调整。
- 增加持久化求职待办、面试安排 CRUD、月/周日历视图及从面试创建准备待办。
- 展示岗位分布、六周状态事件趋势、待办和近期面试统计；全部来自用户实际记录，空数据不使用演示内容填充。
- 验收：后端工作台测试、前端 lint/build 及用户浏览器布局和交互验收通过。

### Phase 10：智能岗位推荐（v0.2.0）

- 基于本次搜索的临时结果、明确筛选条件及候选人画像排序。
- 展示可追溯的匹配理由、技能差距和未知信息，支持用户反馈。
- 首版以本地规则对已确认的求职偏好和当前在线简历排序，不调用模型；附件简历需先确认解析为在线简历。
- 反馈保存在服务进程内存，不改画像或岗位数据库；分数标注为参考分，不代表录用概率。
- 验收：推荐不越过已启用来源和显式条件，不自动保存岗位或更改画像；无候选人资料时回退到最新排序并提示完善。自动化与用户浏览器验收通过。

### Phase 11：岗位订阅与查新（v0.2.0）

- 保存岗位搜索条件，支持手动、每日、工作日、每周、间隔天数和每月查新；失败来源与无新结果区分展示。
- 运行结果仅作为可查看预览，用户确认后才进入正式岗位库。
- 验收：去重可解释、原始来源可追溯；无结果不推断岗位关闭；界面说明本地后端运行限制。
- 实际交付：新增订阅配置、北京时间轻量定时器、运行历史与短期结果预览；支持按 Provider 展示部分失败、稳定去重、用户确认后保存到岗位管理。预览保留 30 天，不接外部通知渠道；关闭/休眠期间不执行，服务端重启后至多补跑一次。
- 验收结果：离线 API/服务测试、前端 lint/build 及用户浏览器验收通过。真实 Provider 可用性仍取决于用户配置和招聘网站状态。

### Phase 12：Agent 工作台协作与评测（v0.2.0）

- Agent 可使用当前已实现的岗位搜索/分页、岗位链接解析、岗位管理与分析、校招资讯查询、推荐反馈、个人画像/在线与附件简历、工作台待办/面试、投递状态管理、岗位订阅和来源状态检查。
- 用户明确要求时可从 Agent 发起或取消 BOSS 官方登录；登录状态和进度复用现有 Provider 接口。
- Agent 可查询订阅条件和运行记录，按用户要求手动查新（只生成岗位预览）；可提出创建、修改、暂停/恢复和删除订阅，来源受岗位搜索页当前选择约束。
- 所有业务数据写入、修改、删除和简历切换必须先确认；待处理确认卡片跨会话切换仍保留；上传本地简历文件仍在个人画像页面完成。
- 操作轨迹记录工具名、脱敏白名单参数摘要、结果摘要、状态和工具执行耗时，不记录隐藏推理；耗时不包含等待用户确认的时间。
- 真实 LiteLLM SSE 评测脚本扩展为 12 个场景，支持 `--case` 定向复测。修订后完整评测通过 12/12；首轮发现的投递状态查询冗余调用已由定向与完整回归验证修复。
- 自动化验证：`tests/test_agent.py` 28 项通过、全量离线测试 132 项通过，覆盖订阅创建与暂停确认前不写入、确认后生效、手动查新只写运行预览等路径；前端 lint/build 通过。真实模型单轮评测数据见 `docs/agent-evaluation.md`。
- 验收：确认前无写入，拒绝/重复处理/SSE 中断均不产生未授权变更；评测报告注明样本范围与运行环境。
